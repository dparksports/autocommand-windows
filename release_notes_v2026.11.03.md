# AutoCommand v2026.11.03

Self-contained Windows build — **no .NET installation required**. Unzip and run `AutoCommand.exe` as Administrator.

## Highlights

- **🚫 New tab: Block Proof — evidence that your telemetry blocks work.** A hosts-file pin fails invisibly: the beacon is refused before a packet touches the NIC, and success looks identical to "it gave up." Block Proof turns that silence into rows. It reads every telemetry pin in the hosts file (markers written by Shields Up or this app), shows its mode, and — with **sinkhole mode** on — points the pin at `127.0.0.1`, where AutoCommand owns a loopback listener on port 443. Each attempt completes a real TCP handshake, its TLS ClientHello is read for the intended hostname (SNI), the peer PID is captured from the OS connection table while the socket is live, and WMI adds the process image and full command line. Then the connection is closed with **no reply, ever**. Attempts land in a live feed with cumulative per-domain and per-process counters, persisted as plain JSONL next to the app (`telemetry_proof.jsonl`), exportable to CSV. Nothing leaves the machine in either pin mode. If another local server already owns `127.0.0.1:443`, the sinkhole stays off and says so — the pin keeps blocking either way. Pin addresses are only ever `0.0.0.0` or `127.0.0.1`, enforced in code.
- **Telemetry opt-outs now hold — or say they don't.** Opt-out writes preserve JSON token types (boolean `false`, not quoted `"false"`), are verified by re-reading the file, and the result dialog states that already-running processes keep the old setting until restarted. A value that matches the off-switch but has the wrong type — the exact way a quoted `"false"` gets read back as *on* — is reported in amber as **Opt-out not honored** with the raw value in the evidence line, never as a fake green "Opted out." Reverts restore the previous token exactly as it was.
- **Network enforcement for apps that ignore their own switch.** Rules can carry an `enforce` block: the telemetry domain is pinned to `0.0.0.0` (silent) in the hosts file under a marker line carrying the rule id — system-wide, one-click reversible, never touching user edits. Removal is address-agnostic, so a pin switched to sinkhole mode in AutoCommand still reverts cleanly from Shields Up.
- **New rules: `ultralytics-offline`** — `YOLO_OFFLINE=1`, the library's own honored offline switch (also disables auto-install and update checks; model weights must already be on disk) — and the corrected `ultralytics-sync` rule with typed write, type-aware probe and the enforcement block.
- **In-app usage telemetry, fully removed.** The last analytics code paths and their legacy registry leftovers are gone — the app now collects nothing, and cleans up after its own past.

> **Note:** run elevated as usual — Sysmon event reading, the raw-socket capture and the sinkhole listener need administrator rights. The telemetry rules knowledge base ships at `Assets\telemetry_rules.json` next to the exe; edit it to add apps without a rebuild.
